# M3 integration contract (implementation working notes)

This milestone implements editing and explicit translation, preserving the gray shrinking sticky title. M2 remains separately tracked; exact quote sources use a small ID endpoint, not a claim of complete M2 pagination.

## Backend contract

- Content identity: `{kind:'topic'|'post',id}`. First post uses topic ID, not `first-` prefix. Public topic/detail records expose `version` (integer >=1), `editedAt`, `language`, `bodyFormat`, and `releaseOrder` for topics. Replies additionally expose `quoteRefs` and `attachments`. Hidden replies are omitted everywhere public and from visible reply counts.
- `GET /api/content/{kind}/{id}/source`: `{content:{kind,id,topicId,version,author,userId,title?,body,bodyFormat,language,createdAt,editedAt,attachments,quoteRefs}}`. Visible source only, even for administrators; hidden sources return404. Use a source dialog when not in currently loaded reply window; never imply full M2 pagination.
- `POST /api/content/{kind}/{id}/edit`: JSON `{expectedVersion,expectedUserId,body,bodyFormat,language,title?}`. Owner or admin, no muted/banned actor, reread identity after request body. Topic title3–140/body5–12000, reply body1–6000. `bodyFormat` plain|markdown. Author language `und` supported. Existing published attachments preserved on edit (read only); new uploads allowed for reply creation. Returns `{content}`. HTTP409 `revision_conflict` retains local draft; fetch latest source explicitly, never overwrite or retry with a new expected version automatically.
- `GET /api/content/{kind}/{id}/history`: signed-in owner/admin only, visible content only; `{revisions:[{version,body,title?,bodyFormat,language,editedAt,editor}]}` latest50. Hidden body/history not public.
- `POST /api/content/{kind}/{id}/visibility`: `{hidden:boolean,expectedUserId}`. Owner/admin may hide; only admin restores. Topic uses existing recoverable topic mechanism. Reply hiding is reversible and audited; no physical deletion. UI confirm before hide, disabled protected actions still enforced on server.
- `POST /api/content/{kind}/{id}/translate`: `{target,expectedVersion}`; explicit click only, including five manual UI languages. Anonymous allowed with origin limit; separate account/IP daily quotas plus existing global char budget/concurrency. Returns `{content:{kind,id,topicId,version,sourceLanguage,language,automatic,fromCache,bodyFormat,body?,document?}}`. Plain `body` string; Markdown `document` opaque safe parsed tree rendered via new `renderMarkdownDocument(container,document)` from markdown.js. Do not pass a document to innerHTML. If same source/target, automatic false and original shape returned. Timeout/budget/visibility/version failure keeps original and permits retry. Never translate quotes, account/admin/private data automatically.
- New replies keep existing `POST /api/topics/{id}/replies`: `{body,bodyFormat,language,expectedUserId,clientRequestId,attachmentIds,quotes}`; all fields except body optional for old clients. Same account+UUID replays same request, conflicting content409. Returns `{post,replayed}`; body max6000. `quotes` max6 `{kind,id,version,excerpt}`; excerpt <=1500 chars, sources must be visible in same topic, expected source version current on submit, text checked against source. Legacy quote string remains display compatible.
- Serialized quoteRefs: `{kind,id,topicId,version,excerpt,author,available}`. Hidden source returns unavailable metadata WITHOUT excerpt/author. Frontend quotes must be text nodes, linked to source via ID/source dialog. Selecting text only within a single original visible post body; translated selections cannot pretend to quote original. Repeated selections can add up to6 references.
- Existing attachment upload,retain,delete APIs remain; unpublished IDs bind to specific reply. Gallery metadata unchanged; forTopic excludes reply images, forPost respects parent/reply visibility. No edit-time removal of published images in this milestone.
- New topic language must be explicitly chosen; default und, not inferred from interface. Existing stored languages retained as legacy values.

## Frontend ownership

Frontend worker owns dist/app.js, dist/composer.js, dist/compose-drafts.js if needed, dist/m3-*.js/css, dist/select-topics.js, dist/index.html, ops/check-i18n.mjs and relevant frontend tests. Root owns shared dist/markdown.js/core, server/backend/migrations, release/announcement ops, documentation. Shared editor core should be extracted from existing composer formatting and used by new topic/reply/edit; preserve #reply-text for reading focus. Reply toolbar/preview/language/images, topic/post edit dialog with conflict state/history, multi-selection quotes/source dialog, public gallery lightbox, per-post explicit translate/original/retry and automatic badge. Five UI languages manually maintained; dynamic component refresh preserves local edit/reply text and cancels stale requests across route/actor/target/version. Maintain gray navigation and desktop/mobile layouts. Rebuild or refresh reading DOM anchors after translated/edited content replacement while preserving temporary return point.

## Release notes ordering

Operator-only `topics.release_order` nullable integer exposed as releaseOrder. In site category version notes with this field sort100(V1.0),110(V1.1),120(V1.2), while ordinary forum sorting stays unchanged. Keep actual timestamps; V1.0 clearly labeled retrospective overview. Do not assign releaseOrder from public posting payload. Announcements only publish after M3 validation/deployment.
