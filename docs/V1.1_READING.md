# V1.1 帖子阅读体验

用户确认：电脑右侧导航、较窄屏幕横栏、手机底部双按钮；直达回复与回到原位置；本次上线后在站务与公告发布操作说明。不是M2/M3完整交付。

## 实现

- `dist/reading-nav.js`协调正文、回复区、最新回复和现有输入框；`reading-position.js`保存本次页面内的内容锚点与偏移，无跨设备或持久阅读记录。
- `reading-nav.css`分别安排宽屏右列、紧凑横栏、手机底栏；容器放在详情区，固定手机底栏在body，避免容器成为固定定位包含块。
- `reading-i18n.js`人工维护五语；字典检查覆盖控制器、HTML键和插值。
- 标题回复数可点击；空回复提供首次回复入口；输入聚焦时收起手机底栏，搜索入口移至话题顶部。
- API新增可选`replyWindow=first|latest`，默认兼容first。分别读取最早/最新250条、按时间和ID稳定排序；返回总数、已加载量、前后是否还有回复。最新窗口保留正序阅读，避免把第一批最后一条称作最新。不属于完整分页。
- 回复完成只更新原话题、原账号及原输入节点，不能清掉切换到另一话题后输入的草稿。
- 公告草稿为`V1.1_ANNOUNCEMENT.json`，标题“V1.1 帖子阅读体验更新”。通过显式管理员操作发布，不加入启动种子；固定请求UUID利用现有回执防止重试重复发帖。

## 后续维护

不要把正文默认折叠，也不要为右导航强行收窄整个桌面页面。较窄桌面读实际sticky横栏高度确定跳转留白；手机注意安全区、软键盘、弹窗、抽屉和编辑器。回复很短时受页面底部钳制，仍须提供返回入口。切换话题销毁监听和返回点，语言重绘保留草稿与当前话题窗口。

图片加载可能改变原位置；返回以内容锚点为主，在用户继续操作前校正未加载图片。真实设备软键盘、IME及读屏独立验收，不由桌面模拟视口证明。
